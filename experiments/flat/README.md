# Flat experiments (`experiments/flat/`)

This directory is the Phase C deliverable from issue #1
("Establish Spherepop as a language: history, evidence, experiments, and
implementation convergence"): a suite of tiny, standalone event-sequence
fixtures with no GUI, game engine, nested build system, network access, or
hidden mutable state. Each fixture is small enough to predict on paper,
runs with one command, and is checked against a checked-in expected
result by more than one independent implementation.

## Why this exists

A parser alone does not establish semantics; a demo alone does not
establish a language. This suite targets a narrower, checkable claim:
that the four canonical primitives (`Pop`, `Refuse`, `Bind`, `Collapse`)
have a single stable operational meaning that independent implementations
can agree on, and that the documented derived operations (`Link`,
`Unlink`, `Choice`, `Merge`, `SetMeta`) really do desugar into that basis
with no hidden fifth primitive.

## Running everything

```sh
./run_all.sh
```

This runs the fixture suite against four independent implementations,
regenerates `CONFORMANCE.md` (the Phase D "generated conformance
matrix" deliverable), and fails (non-zero exit) if any implementation
disagrees with a fixture's own recorded expectations:

- **Python oracle** (`run_python.py`) — a from-scratch reimplementation
  of the kernel semantics, written without importing or calling into the
  Rust crate.
- **Rust reference kernel** (`../../spherepop-kernel`, via
  `cargo run --bin fixtures`) — the existing dependency-free reference
  implementation of the `(H, Ω)` world model, the Arbiter, and the
  collapse rules.
- **C kernel** (`../../compiler/tools/fixtures`, built as the CMake
  target `sp_fixtures` inside `compiler/build/`) — a third, standalone
  C port of the same event/history/arbiter/collapse/sugar model,
  deliberately independent of `compiler/`'s general-purpose Bubble
  interpreter (whose own `Bind`/`Collapse` are still known to diverge
  from the canonical semantics -- see `IMPLEMENTATIONS.md`).
- **Go implementation** (`../../spherepop-go`, via `go test` and
  `go run ./cmd/fixtures`) — a fourth standalone realization of the
  event/history/arbiter model and SPHIST/1 encoder/decoder.

All four runners read the *same* JSON fixture files in `fixtures/`, so
agreement between them is a genuine four-implementation
cross-implementation conformance result — the "Portable" evidence
criterion from the tracking issue.

Run them individually with:

```sh
python3 run_python.py                       # Python oracle only
cd ../../spherepop-kernel && cargo run --bin fixtures   # Rust kernel only
(cd ../../spherepop-go && go test ./... && go run ./cmd/fixtures ../experiments/flat/fixtures)  # Go only
(cd ../../compiler/build && cmake .. && make sp_fixtures && ./sp_fixtures)  # C kernel only
python3 generate_conformance_matrix.py       # regenerate CONFORMANCE.md only
```

## Conformance matrix (Phase D)

`CONFORMANCE.md` is generated, not hand-written -- it is regenerated by
`generate_conformance_matrix.py` every time `run_all.sh` runs, so it
cannot drift from what the adapters actually reported. It records, per
fixture, PASS / FAIL / SKIP (manual fixture) for every adapter that
could be exercised, plus an explicit **Blocked adapters** section for
implementations that could not be run at all in the current
environment -- each with the concrete reason established by direct
investigation, not a placeholder. As of this writing that section
covers:

- **SphereForth (`prototypes/sphereforth_gforth.zip`)**: gforth could
  not be started in this environment (a snap-confinement failure, and
  separately a missing `libtool` needed by gforth's own FFI
  bootstrapping). The source was read and traced by hand instead (see
  `IMPLEMENTATIONS.md`); wiring a real adapter needs an environment
  where `gforth` actually runs.

Per the tracking issue's instruction, these are recorded as explicit,
investigated blockers rather than silently absent rows or weakened
fixtures.

## Fixture format

Each fixture is one JSON file in `fixtures/`. Fields:

| Field | Meaning |
|---|---|
| `name` | Human-readable identifier, should match the filename. |
| `invariant` | The one property/distinction this fixture is testing. |
| `explanation` | Plain-language note on why a bare state snapshot would be insufficient to observe this invariant. |
| `initial_option_space` | The finite initial `Ω`, as a list of object ids (small non-negative integers). |
| `certified_rules` | Names of collapse rules the Arbiter will accept in this fixture (an uncertified rule name must be rejected). |
| `events` | The event sequence to submit, in order (see "Event ops" below). |
| `expect` | The expected final state (see "Expectation fields" below). |

An event without `manual: true` is executed. A fixture with two
top-level `history_a`/`history_b` blocks instead of a single
`initial_option_space`/`events` block (currently only `08_meld.json`)
uses the Meld two-history schema instead (see "Meld fixture schema"
below); no fixture is currently marked `manual: true`.

### Meld fixture schema

`08_meld.json` doesn't fit the single-Arbiter event-stream schema above
because Meld (the free monoidal composition of two independently-
generated histories) operates on two `History` values directly, before
either is submitted to an Arbiter. Its schema is instead:

| Field | Meaning |
|---|---|
| `history_a`, `history_b` | Each an independent sub-history: `{"initial_option_space": [...], "events": [...], "certified_rules": [...]}`, submitted through its own Arbiter exactly like the single-history schema above. |
| `expect_melded_history_len` | The length of the melded event log, i.e. `len(history_a) + len(history_b)` (event-log concatenation, matching `spherepop-kernel::History::meld`). |

A runner detects this schema by the presence of `history_a` (rather
than `initial_option_space`) at the top level of the fixture.

### Event ops

Each entry in `events` is `{"op": "<name>", ...op-specific fields...}`.
The four primitive ops map directly onto `EventKind`; the five sugar ops
expand into primitive events only (this is checked structurally by
construction, since the runners' sugar functions cannot return anything
else):

| `op` | Fields | Expands to |
|---|---|---|
| `pop` | `a` | `Pop(a)` |
| `refuse` | `a`, `reason` | `Refuse(a, reason)` |
| `refuse_bind` | `a`, `b`, `reason` | `Refuse` targeting a Bind pair |
| `bind` | `a`, `b`, `tag` | `Bind(a, b, tag)` |
| `collapse` | `rule` | `Collapse(rule)` |
| `link` | `a`, `b`, `tag` | `Bind(a, b, tag)` |
| `unlink` | `a`, `b` | `Refuse(Bind(a, b), "relation withdrawn")` |
| `choice` | `taken`, `rejected` | `Pop(taken)`, `Refuse(rejected, "not selected by Choice")` |
| `merge` | `a`, `b`, `rule` | `Bind(a, b, "merge")`, `Collapse(rule)` |
| `set_meta` | `object`, `key` | `Bind(object, key, "__meta__")` |

An event may additionally set `"expect_reject": true` (with an optional
`"expect_error"` prefix, e.g. `"PopOutsideOptionSpace"`) to assert that
the Arbiter must refuse this proposal outright and leave the history
length unchanged — this is how the `10_invalid_event` fixture is
expressed.

### Expectation fields (`expect`)

All are optional; only the fields present are checked.

| Field | Checked against |
|---|---|
| `option_space` | Final `Ω` (set equality). |
| `committed` | Objects committed via `Pop`. |
| `bound` | List of `[a, b, tag]` triples that must all be present in the Bind facts (subset check). |
| `refused_count` | Total number of `Refuse` events recorded. |
| `history_len` | Total number of primitive events actually appended. |
| `observed_rules` | Ordered list of rule names passed to `Collapse`, in submission order. |
| `quotient_same_class` | List of `[a, b, bool]`: whether `collapse_quotient` (the identifying rule Merge-sugar uses) places `a` and `b` in the same class. |
| `quotient_honoring_refusals_same_class` | Same, but for the variant that excludes withdrawn (`Unlink`-ed) Bind pairs. |
| `meta_keys` | List of object ids that must appear as keys under the dedicated `SetMeta` collapse rule. |
| `deterministic_replay` | If `true`, replaying the resulting history twice from the same initial `Ω` must produce byte-for-byte identical state. |
| `canonical_history_fnv1a64` | Encode the replay input as SPHIST/1, check its 16-digit lowercase FNV-1a-64 digest, decode it, and require fresh-state replay to equal the original state. |

## Known gaps / follow-up work

This suite intentionally does not yet close every item in the tracking
issue's Phase C checklist:

- **Meld** (`08_meld.json`) is now executed end-to-end by all three
  runners via the two-history schema (see "Meld fixture schema" above),
  not just structurally validated. This was verified directly against
  `spherepop-kernel`'s own `History::meld` semantics (event-log
  concatenation).
- **Replay** (`09_replay.json`) now exercises the stronger Phase B claim.
  Each adapter encodes the complete replay input as the canonical
  [SPHIST/1 envelope](HISTORY-WIRE-V1.md), checks the expected FNV-1a-64
  digest, decodes the bytes independently, and replays the decoded history
  from a fresh state initialized only by the decoded option space. FNV is
  a portable regression identifier, not an authenticity mechanism.
- Three implementations are now exercised (Rust, Python, C); see
  `CONFORMANCE.md`'s "Blocked adapters" section for the concrete,
  investigated reason Forth isn't yet, and `IMPLEMENTATIONS.md` for
  Haskell/Racket (historical artifacts using an unrelated calculus, not
  adapter candidates until/unless they're rewritten against the
  canonical primitives) and shell (no such implementation exists in this
  repo currently). This suite's JSON format was chosen specifically so
  adapter work can proceed independently per implementation without
  touching the fixtures themselves.
